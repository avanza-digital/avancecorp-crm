FINDINGS:

[P2] Pending leads in non-`nuevo` stages are counted but invisible as pending in the list
File:
`CRM-Avance-Corp/app/src/lib/use-etapa-visible.ts:8`, `CRM-Avance-Corp/app/src/screens/hoy/leads-recibidos-hoy.tsx` (row badge hunk)
Problem:
The badge counts leads with no qualifying activity since `tenencia_desde`. The SQL predicate ignores `etapa`. The row label comes from `etapaVisible`, which only evaluates management when `lead.etapa === 'nuevo'`. Any other stage returns its stored stage label directly.
Evidence:
- `etapaVisible` line 8: `if (lead.etapa !== 'nuevo' || ...) return { k: lead.etapa, ...ETAPA_INFO[lead.etapa] }`.
- The SQL `p_gestion` predicate has no etapa condition.
- The E2E fixture itself shows a lead with `tenencia_desde` today and `etapa: 'propuesta_enviada'`, so reassignment today with a carried-over stage is a realistic case. The fixture gives leads 0–1 activities, so the scenario "advanced stage + no current-tenure activity" is never exercised.
Impact:
A lead reassigned today in `contactado` or `propuesta_enviada` shows "Contactado" or "Entrevista realizada" while still counted in the orange badge. The analyst sees N pending but cannot find which rows they are. This is the inverse of the user's goal: the lead looks touched, but the system demands management. Live data today is all `nuevo`, so the current impact is low, but nothing prevents the case.
Recommendation:
Decide and document one of two options:
- (a) Accept "stage shown, pending implied" as a product decision. Add a test pinning that behavior.
- (b) Preferred: add a small per-row "Sin gestionar" marker for rows that match the pending predicate. This works if the RPC row already exposes `gestion_vigente`, which `etapaVisible` reads for real sessions, so it should. In demo, use `tieneGestionVigente`. No backend change is needed.

Also add a unit/E2E case with `etapa: 'contactado'`, `tenencia_desde` today, and no activity, asserting both the count and the row rendering.

[P3] Tab accessible name no longer conveys what the number means
File:
`CRM-Avance-Corp/app/src/screens/hoy/agenda-leads-hoy.tsx` (badge hunk)
Problem:

Evidence:
The tests assert the accessible name `'Leads de hoy 53'` while the panel says "55 leads recibidos hoy". `title` on a non-focusable descendant does not reliably contribute to the tab's name or description.

Add sr-only text inside the badge, for example `<span className="sr-only"> sin gestionar</span>`. Update the name assertions accordingly. Keep the visible digit unchanged.
