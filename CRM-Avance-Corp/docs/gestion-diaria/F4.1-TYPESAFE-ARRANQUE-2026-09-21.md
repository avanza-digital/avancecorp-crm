## Qué se implementó

Un [ensayo técnico reproducible](../../scripts/gestion-diaria-typesafe/README.md)
de 20 casos sintéticos escritos por Codex: los siete resultados de llamada,
seguimiento sin descarte, negaciones, referencias temporales, notas vacías/genéricas
e instrucciones insertadas en una nota. No es un dataset humano ni una calibración.

La pregunta `Choice` tiene tres salidas: compatible, posible contradicción e
información insuficiente. El estado contiene solo reglas, resultado y nota;
las etiquetas esperadas y los otros casos no viajan en la petición aislada.
La skill `typesafe-ai` orientó este contrato y la separación entre juicio,
incertidumbre y decisiones que siguen perteneciendo al código y al supervisor.

El CLI no acepta archivos externos y por defecto no lee credenciales ni usa red.
`--vivo` requiere una acción explícita, realiza 20 peticiones independientes,
como máximo cuatro simultáneas, 15 segundos por petición y sin reintentos.
Conserva modelo efectivo por caso, probabilidades, latencia y tokens reportados.
Los fallos técnicos, respuestas ausentes e inválidas se separan de errores del modelo.
Nunca imprime claves, errores originales o trazas; no activa funcionalidad.

Se reutilizó únicamente `scripts/jev/cliente.mjs` del taller principal, sin modificarlo:
SHA-256 `4505924b4e6684d0c49b2ae254e528c308040764f1d45ee7e9be4a72c08d739a`.
Los demás archivos y cambios concurrentes de aquel toolkit no forman parte de esta entrega.
Las credenciales permanecen fuera del repositorio y del navegador.

cero errores de servicio, cero ausentes, cero inválidas, una falsa alerta y cero
contradicciones omitidas respecto de estas etiquetas sintéticas. 12.328 tokens de
entrada, 1.102 de salida y 4.601 ms de duración total con concurrencia cuatro.
No se convirtió ese consumo a dinero sin verificar la tarifa aplicable.
Evidencia por caso: [JSON del control aislado](typesafe/ensayo-aislado-2026-09-21.json).

El desacuerdo es `c04`: resultado «No contestó», nota «Se gestionó». Se esperaba
información insuficiente; el modelo eligió posible contradicción con confianza
0,26 y probabilidades 0,14 / 0,51 / 0,35. No se bajó un umbral ni se repitió hasta
obtener un resultado favorable. El caso queda para validación humana. La confianza
no prueba verdad ni permite activar el producto.

**Apoyo técnico probado.** El toolkit Jev existente del taller principal pasó sus
22 tests. Para localizar dónde se excluyen etiquetas esperadas, ordenó primero
`crearSolicitud` (1,69), luego `resumir` (1,47) y `respuestaValida` (0,35).
Ninguno alcanzó el corte existente de 2 puntos: el ensayo no acredita una conclusión
automática. Los tests deterministas sí verifican la exclusión de etiquetas.
[Evidencia del ensayo técnico](typesafe/apoyo-tecnico-2026-09-21.json).
Jev ayuda a ordenar evidencia, no sustituye a Claude, Codex ni los gates.

SECONDARY_REVIEWER sin herramientas, ediciones ni recursión. Dictamen:
`CHANGES_REQUESTED`. No se presenta como aprobación posterior del código corregido.

La advertencia P1 sobre `package.json` era una hipótesis por evidencia no adjuntada:
se verificó el diff y la ejecución completa. `check:scripts` llama exclusivamente
a `test:gestion-diaria-typesafe`, con checks de sintaxis y tests deterministas;
no llama a `--vivo` ni requiere credencial. La evidencia JSON de los primeros
ensayos ya estaba guardada aunque no se había adjuntado al reviewer; se enlaza aquí.

Se mantiene la validación estricta de probabilidades: ninguna ejecución observada
incumplió el contrato. Si el proveedor cambia el redondeo, se registrará respuesta
inválida, no una contradicción omitida. Las observaciones sobre permisos del archivo
de clave y clasificación de timeout anidado pertenecen al cliente reutilizado;
no se lo bifurcó ni se lo modificó. No afectan los reintentos de este ensayo (uno).
