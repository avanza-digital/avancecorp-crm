[P2] Realtime partition keys are date-bound, so the "exact reviewed differences" gate will fail once partitions rotate
File: diferencias-externas-v5.json; diferencias-reales-v5.json
Lines: all `realtime.messages_2026_09_11` … `messages_2026_09_17` keys (140 of 172)
Problem: The allowlist hard-codes daily partition names (today −3 … +3). Realtime creates and drops these partitions on the parent every day.
Evidence:
- Parent has Sep 11–17 on 2026-09-14.
- The branch has none.
- The hashes are date-independent: every partition carries the same MD5s (`2aa2f602…`, `1042dfa2…`, `245213ce…`, `3d61599c…`, `b8ab7a2a…`).
Impact:
- A paired capture after the next rotation, or across midnight UTC inside the 60 s window, produces new or missing keys and stops.
- That is correct fail-closed behaviour, but it invites regenerating the manifest without review, which defeats "only exact reviewed pairs".
Recommendation: Before running the gate, either:
- run the paired capture and merge within the same partition window and record the timestamp; or
- pre-define and review a narrow rule: key regex `^(relation|column|constraint):realtime(\.realtime)?\.messages_\d{4}_\d{2}_\d{2}(_pkey|_inserted_at_topic_idx)?(\..+)?$`, values restricted to the fixed MD5 set above, and a per-partition key shape (10 columns + 2 indexes × 2 columns + 2 constraints + 3 relations).

Also treat `supabase_realtime_messages_publication` table membership as varying with the same date set. Everything else stays exact.
