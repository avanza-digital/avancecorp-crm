[P2] `con_historia` hides client profiles with any economic history, not only demo history (hypothesis: raw reader definition not attached)
File: `supabase/migrations/20260914025926_crm_f8_excluir_fuentes_demo.sql`
Lines: 96–99, 108–121, 127–130
Problem: The comment says the exception must not return a person "cuya única historia económica es demo". The predicate actually implemented is "has any history in contratos/inversiones/cierres AND no row in `fuentes_reales`":
- No branch filters `es_demo`.
- No branch filters `cierres_externos.anulado_en`.
- No branch filters contract state or category.
Evidence: Lines 110–120 have no demo or annulment filters. Visibility through fuentes comes only from `private.cartera_f5_fuentes_reales()`. Suppose the raw reader excludes annulled cierres or some contract states; the test fixture's `anulado_en:null` suggests annulment is modeled. Then a client whose only history is an annulled or excluded non-demo row was visible through the profile exception before this migration and is hidden after it.
Impact: This is an unintended regression outside the demo contract. A legitimate client disappears from the list, ficha, cuentas and documents. No test covers it: every `con_historia` test uses demo rows.
Recommendation: Choose one of these:
- (a) Restrict `con_historia` to demo origins, meaning demo contracts, their inversiones, and demo cierres with their lead links.
- (b) Keep the wider predicate, but first prove with read-only production SQL that no client-profile person has non-demo history outside the raw reader, and correct the comment.

Either way, add a test for a client profile whose only history is a non-demo row excluded from the raw reader, such as an annulled cierre. Note that (a) changes the hash `db749fbf…` in both the forward and reversal tables.
